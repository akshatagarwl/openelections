# Product

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
React/Vinext on Vite+, Base UI controls, Tailwind v4 theme and layout utilities, TypeScript, and @shadcn/lint. Preserve the accessible server-rendered narrative, Base UI disclosures, custom interactive diagrams and exhibition design.

## Users
Citizens, journalists and technical readers who can scrutinise and share a nonpartisan demand for an enduring open-source publication policy for election software.

## Product Purpose
OpenElections.in explicitly demands a standing publication policy for every ECINet/ERONet component that implements election rules or mediates statutory powers: current code, future modules and every update. Include supporting dependencies, review coverage, version history, configuration changes and deployment evidence. Current Form 6, officer-access and restoration reports illustrate the need; they must never define or cap the demand's scope. Publication must not wait for a controversy. The documentary substantiates this enduring demand; education supports advocacy. Nonpartisan does not mean neutral about publication.

## Capabilities and Constraints
Primary-source citations for factual claims. Clearly distinguish ECI statements, analysis, unknowns and advocacy demands. No allegation of manipulation or assertion of an existing legal source-publication duty. No petition, tracking, personal data collection or official affiliation. Fast, responsive and accessible. The website itself is MIT-licensed. The demand covers all current and future code that implements election rules or mediates statutory powers, regardless of whether it is disputed. Public auditability is a continuing release obligation we advocate, not a one-time code dump or review. The boundary protects sensitive data and operational secrets; it is not a fixed list of currently questioned modules. Distinguish source availability from licensing permissions to run, modify and redistribute code. Exclude voter/staff data, credentials, private keys and live operational secrets.

## Brand Commitments
Interactive investigative documentary. Minimal text, strong typography, diagrams, scroll-driven motion and calm technical credibility. User-selected hero wording: “Make source code of ECINet/ERONet public.” Use the real public repository https://github.com/akshatagarwl/openelections for website source, rather than a ZIP download.

## Evidence on Hand
ECI releases published by PIB, Estonian election authority documentation and Swiss Federal Chancellery examination materials. Three user-supplied Indian Express articles: an original investigation, an explainer and an editorial. Label reporting as reporting and opinion as opinion; do not pretend this site possesses the internal notes. A review announcement is not a completed audit. An unavailable public artifact is not evidence of wrongdoing.

## Product Principles
- Make claims testable, not partisan.
- Protect personal data while explaining public-interest software disclosure.
- Separate documented facts from demands; state the demand clearly rather than softening it into an optional proposal.
- Keep citations adjacent and accessible.

## Accessibility & Inclusion
Keyboard usable, semantic structure, reduced-motion support and responsive mobile reading. WCAG AA target. Narrative and references are server-rendered; Base UI disclosure controls require JavaScript, with no alternate native UI. Clipboard failures show explicit feedback rather than downloading a fallback file.
